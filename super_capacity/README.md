# STM32F103RCT6-RM超级电容控制板配套程序-V1.0.0

本文档为 RM超级电容控制板 程序说明。
主控芯片为STM32F103RCT6，对应硬件：

* RM超级电容控制板 V0.5.1
* 淘宝LT8790可调升降压恒流模块

## 1 模块使用

### 1.1 设置是否使用调试模式

使用拨码开关Bit1控制上电后是否开启调试模式。

#### 1.1.1 调试模式

* 此时上电后不启动充电，需要按下五轴按键才能启动充电和底盘供电。
* 调试模式中，未手动开启充电时，无论超级电容是否有电，控制板都不会启动底盘供电。

#### 1.1.2 正常模式

* 此时上电后直接启动超级电容充电，超级电容电量正常后会自动启动底盘供电。

### 1.2 LED显示说明

板载LED会显示当前的工作状态。

* LED1闪烁：CAN通信正在接收数据
* LED2闪烁：超级电容恒功率控制算法正常运行
* LED3亮起：正在向底盘供电
* LED3熄灭：没有向底盘供电

### 1.3 缓冲能量使用策略说明

正常连接超级电容控制板和底盘主控的CAN通信信号线，此时超级电容控制板会从底盘主控中获取到裁判系统的缓冲能量数据。
利用底盘裁判系统缓冲能量数据，超级电容控制板会适当增大充电功率设定值，将裁判系统缓冲能量使用到剩余5J左右。

* 如果超级电容控制板检测到底盘主控CAN通信异常，或底盘主控通过CAN通信告知当前裁判系统通信异常，超级电容控制板会自动恢复到纯本地功率控制模式，不再使用缓冲能量，防止出现超功率。如果底盘主控的CAN通信恢复，超级电容控制板会继续自动调节功率以使用缓冲能量。

### 1.4 底盘通信说明

与底盘的通信包括发送和接收两个模块。
在`mod_can.c`中编写有专门发送和接收CAN报文的线程。

#### 1.4.1 向底盘发送电容电量和底盘实际功率

`void CAN1_SEND_CAPState(float CAP_Percentage, rt_uint16_t Power_Now)`
该函数能使用CAN通信发送float型电容电量百分比，大小0~1之间。同时也会发送uint16型的当前底盘功率实际值，发送数据单位为0.1W。

#### 1.4.2 接收底盘发送的缓冲能量数据和当前功率上限数据

* `mod_can.c`中的CAN接收发送处理线程，调用了`func_can.c`中的`Robostate_NewData`函数，对底盘主控发回的数据进行处理。
* `mod_can.c`中的`RoboState_Type RoboState_Data`结构体中存储了接收并处理后的底盘主控发来的数据。

## 2 新模块参数调节

* 每套硬件可能都需要进行参数调节，才能达到算法的最佳效果。
* 算法本身不需要调参，使用新的硬件时，需要对ADC和DAC以及淘宝购买的升降压模块的限流值设定，进行数据标定。

### 2.1 调节前的硬件准备工作

进行数据标定之前，可将超级电容替换为5欧姆功率电阻。并准备接入电流表。

购买的升降压模块需要拆除电流设定值对应电位器旁边的上拉电阻，并将电位器调到接入电路电阻最大。
另外，使用前应该先将用到的模块的电压设定值修改为合适值。用于给超级电容充电的升降压模块的电压设定值应为电容预期满电电压（需要注意不能设定过高，否则可能触发超级电容保护芯片过压泄流，发生危险。）用于给底盘电机供电的升降压模块应设定输出电压24V，用于给电机供电。

* 拆除上拉电阻后，可以用万用表电阻档位测量外部电流设定接口对地电阻，此电阻即为当前电位器接入电路的电阻值，通过旋转电位器角度，可以将接入电路的电阻值调到最大。

### 2.2 ADC-DAC线性标定

使用前需要先用测试程序进行标定。

#### 2.2.1 DAC设定值-输出电压标定

单片机的DAC输出，程序设定值与实际值可能存在一定偏差。

* 先将单片机DAC输出端正确连接到升降压模块上，再开始标定，否则连接升降压模块之后信号实际值可能会再次出现偏差。

* 在程序上设定单片机DAC固定输出一个电压，再测量出此时控制板DAC输出端的实际电压。
* 修改DAC输出电压设定值，重复实验得到多组数据。将数据填入EXCEL。
* 在EXCEL中，以DAC设定值为X轴，以实际输出电压为Y轴，绘制散点图，进行线性拟合，得到K和D（斜率和截距），填入`func_dac.h`中，完成标定数据更新。

#### 2.2.2 DAC输出电压-升降压模块实际限流值标定

* 将超级电容替换为合适阻值的功率电阻，这样当升降压模块输出限流正常工作时，模块输出电压不变，便于测量。
* 在功率电阻上串联电流表，用于测定实际电流。

* 打开电源，通过程序设定一个DAC输出电压，用万用表测量实际输出电压的值并记录。同时记录当前功率电阻上的电流，得到一组对应的数据。

* 修改DAC输出电压，重复测量，得到多组数据。将数据填入EXCEL。
* 在EXCEL中，以实际输出电压为X轴，以实际测得功率电阻电流值为Y轴，绘制散点图，进行线性拟合，得到K和D（斜率和截距），填入`func_dac.h`中，完成标定数据更新。

#### 2.2.3 ADC输入电压标定

使用前，需要先按照硬件理论值修改`func_HW_Pin_set.h`中的设定值。

```{
//核心adc数据需要在func_adc中标定, 此处填写理论值即可
#define HW_ADC_CH_I_IN (13)             //模块输入电流检测通道
#define _HW_ADC_K_I_IN (1/20.0F/0.025F) //换算至单位：A

#define HW_ADC_CH_V_CAP (2)             //电容电压检测通道
#define HW_ADC_K_V_CAP (105.1f/5.1f)    //换算超级电容组供电电压至单位：V

#define HW_ADC_CH_V_IN (12)             //模块供电电压检测通道
#define HW_ADC_K_V_IN (11.0F) //换算模块供电电压至单位：V
```

##### 2.2.3.1 控制板板载总消耗电流检测

* 超级电容仍然替换为功率电阻。
* 将电流表串联接至模块总供电输入端的输入线上，准备测量模块总消耗电流。

* 上电，用程序设定一个固定的输出限流值，读电流表读数并记录。
* 同时通过J-Scope观察ADC测得的实际电流，一同记录，作为一组数据
* 修改输出限流值，重复测量多组数据。将数据填入EXCEL中
* 在EXCEL中，以实际消耗电流为X轴，以ADC测得的电流为Y轴，绘制散点图，进行线性拟合，得到K和D（斜率和截距），填入`func_adc.h`中，完成标定数据更新。

##### 2.2.3.2 控制板板载输入电压检测

* 用学生电源为模块供电。

* 上电，用电压表测量模块实际供电电压。
* 同时通过J-Scope观察ADC测得的工作电压，一同记录，作为一组数据。
* 修改学生电源输出电压，重复测量多组数据。将数据填入EXCEL中。
* 在EXCEL中，以实际电压为X轴，以ADC测得的电压为Y轴，绘制散点图，进行线性拟合，得到K和D（斜率和截距），填入`func_adc.h`中，完成标定数据更新。

##### 2.2.3.3 超级电容电压检测

* 可用学生电源代替超级电容，便于调压，不打开升降压模块即可。

* 上电，用电压表测量超级电容接口实际电压。
* 同时通过J-Scope观察ADC测得的超级电容电压，一同记录，作为一组数据。
* 修改超级电容接口处的电压，重复测量多组数据。将数据填入EXCEL中。
* 在EXCEL中，以实际电压为X轴，以ADC测得的电压为Y轴，绘制散点图，进行线性拟合，得到K和D（斜率和截距），填入`func_adc.h`中，完成标定数据更新。

### 2.3 参数微调

`mod_charge.h`中有可以微调的参数，一般不需要调节。

```{
#define MOD_CHG_I_SET_START (1.5f)//控制未运行时的电流设定值

#define P_FIX_D_SET_DEF (0.15f)// 物理意义：按照功率变化速度进行抑制
```

## 3 程序框架

### 3.1 drv层

drv层包括最基本的通用性驱动文件。暂时有以下几项：

* dac: 自动初始化，可直接设定输出电压（输出未经过标定修正）
* adc: 自动初始化，可直接读取对应通道电压值（输入未经过标定修正）
* canthread: 自动初始化，能完成基本的通用CAN通信发送和接收功能
* iic: 用于OLED显示屏的通信，自动初始化，可以发送
* thread: 记录所有线程的优先级设定值，便于统一修改
* timer: 硬件定时器驱动，用于进行时长小于`1 tick`的精确定时器中断，用于adc采样控制

### 3.2 func层

func层使用drv层中的基本功能，编写了适用于超级电容控制板使用的一些实用性功能。

* adc: 使用drv_timer驱动和drv_adc驱动完成了自动的adc定时采样和滤波计算，并进行了标定数据校正。
* dac: 使用drv_dac驱动完成了设定升降压模块限流值的功能，主要在进行单位换算和标定数据校正。
* buzzer: 蜂鸣器驱动程序。
* can: 使用drv_canthread驱动，完成对接收到的CAN报文的数据解算，并封装对底盘发送的数据的协议。
* HW_Pin_Set: 对硬件直接相关的一些引脚参数进行定义。
* oled: 使用drv_iic驱动，完成OLED的初始化和基本绘图操作封装

### 3.3 mod层

mod层使用func层和少量drv层，完成具有一定综合性的控制模块的封装。

#### 3.3.1 mod_adc

使用func_adc驱动，封装了使用adc数据计算电容电量、底盘实际功率等状态的功能。

#### 3.3.2 mod_can

使用func_can驱动，封装了CAN通信数据发送以及数据处理线程。

#### 3.3.3 mod_charge

使用func_adc\func_dac驱动，封装了充电功率控制算法。

#### 3.3.4 mod_oled

使用func_oled驱动，封装了显示模块。功能包括

* 模块总初始化：OLED外设初始化，清屏等操作。
* 显示或刷新进度条。
* 显示实时功率设定值。

### 3.4 app层

app层使用mod层或func层进行顶层控制。

#### 3.4.1 app_charge

使用mod_can,mod_adc,mod_can驱动，主要利用功率控制算法对缓冲能量进行串级控制，是充电控制的总控程序。

#### 3.4.2 app_oled

使用mod_oled,mod_adc,mod_charge驱动，完成OLED显示的总控。

* OLED总控采用独立的优先级较低的一个线程，有利于在不干扰其它重要程序的运行的前提下，最大限度利用单片机计算能力改善显示效果。

### 3.5 main

主函数使用app层进行总控的初始化，完成后即退出，其余工作由app层中的线程进行控制。
